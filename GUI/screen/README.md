# CENTRAL/GUI/screen —— 统一屏幕壳

> 建立：2026-10-13 ｜ 状态：**v0（空面板，只验证"屏幕能亮"）**
> 关联：[../TASKS.md](../TASKS.md)（任务拆分）、[../status-wall/README.md](../status-wall/README.md)（第一个数据源）、[../../STATUS_WALL.md](../../STATUS_WALL.md)（屏幕的来龙去脉）

## 它是什么

**屏幕的"壳"**：负责把面板摆在 1600×900 上，**不负责数据从哪来**。

```
数据源（各自出 HTTP 接口） ──▶ 屏幕壳（本目录）──▶ 显示器
  status-wall / time / …          壳 + 面板
```

壳只认"面板"这个概念；每个面板自己去取自己那个源的数据。所以以后加系统 =
**加一个面板 + 加一个数据源**，壳不用动。

## 为什么要有 `serve.py`（不能直接开 file://）

面板以后要 `fetch` 各数据源的接口，而 `file://` 页面的源是 `null`，会被 CORS 挡。
从一开始就用 `http://127.0.0.1:8090` 供页面，以后接数据源不用改这一层。

## 现在怎么跑

```bash
python CENTRAL/GUI/screen/serve.py          # 127.0.0.1:8090
# 浏览器开 http://127.0.0.1:8090/
```

中控机上由 systemd 用户服务 `qyn-screen.service` 托管静态页；**kiosk 由
`qyn-kiosk.service` 托管**（`CENTRAL/scripts/systemd/qyn-kiosk.service`）。

```bash
systemctl --user status  qyn-kiosk     # 看它在不在
systemctl --user restart qyn-kiosk     # 重载页面（改了页面就用这个）
systemctl --user stop    qyn-kiosk     # 想拿这台机器干别的时先停掉
```

为什么用服务而不是 autostart 的 `.desktop`（2026-10-13 换的）：

- **崩了能自己回来**：服务带 `Restart=always`；而 `.desktop` 只在登录时跑一次，
  浏览器一崩屏幕就黑着（实测：手工起的 kiosk 几分钟后就没了，服务托管后 40 秒仍在跑）
- **和 `qyn-screen` 有先后关系**（`After=`），不会先闪一下"无法访问"
- 原来那个 `~/.config/autostart/qyn-screen.desktop` **已撤掉**，否则两条路会抢着开窗口

另外，**Firefox 自己的窗口状态也改成全屏了**：它把窗口大小记在
`~/snap/firefox/common/.mozilla/firefox/<profile>/xulstore.json` 的 `sizemode` 里，
原来是 `maximized`（1280×810）⇒ 正常点开 Firefox 是个小窗、不是全屏。
现在写成 `fullscreen`（1600×900），所以**任何方式打开都是全屏**（F11 仍可切换，Firefox 会记住）。

## 标签页：收起 / 依次展开（用户 2026-10-14 的空间管理）

每个面板都是一个**标签页**：同一时刻只有一个**展开**，其余**收到一半宽度**（373px → **186px**），
并按各自特点砍掉次要内容 —— 腾出来的地方留给以后的面板。真实使用时标签页**依次展开**。

| 面板 | 展开 | 收起 | 收起时保留什么 |
|---|---|---|---|
| `DATACENTER` | 373px | **186px** | 只留**数字那几行**（去掉进度条、`THREADS`/`GB` 明细、机器名后的 IP） |
| `NETWORK` | 373px | **186px** | **只留速率**（藏掉 PING）；**例外**：WAN 那块 LOSS 与 PING 都保留，改竖排 |
| `TIME` | 746px | **373px** | 收的是**自己的**二分之一（不是别人的 186）；课时**课程名向左、其余信息靠右**、**DUE 自己滚**（鼠标移上去滚轮即可）、异常栏只留一行计数 |

规则**全部写在 CSS 的 `.panel.collapsed` 里**，渲染逻辑只多了一个 `kind` 类名（`next`/`due`/`alert`）
—— 这样展开/收起只是换一个 class，不会因为两套渲染分支而出现两套 bug。
宽度用**内联样式**钉死（`applyTabs`），不依赖选择器优先级（样式表里 `flex` 明明在、屏幕上却没收到一半，踩过一次）。

### 三种输入（用户 2026-10-15）

| 输入 | 行为 |
|---|---|
| 自动轮转 | 默认每 `TAB_ROTATE_MS`（20 秒）换下一个展开 |
| **鼠标悬停** | 移到哪块，哪块**立刻放大**（盖过自动轮转）；悬停期间**不轮转** |
| **鼠标移走** | **重新计时**，满 20 秒才恢复自然轮转（不会刚移开就被切走） |
| **方向键** `←`/`→` | 选择当前放大的面板（会绕回）；同样重置计时 |

### TIME 的三个子框（用户 2026-10-15）

TIME 展开时里面有三块：**课表 / DUE / 异常**。**没有人工干预时就是现在这样**
（2 节课、5 条 DDL、异常占两行）—— 一旦选中某一块，**只有那块**变成"全部内容 + 竖向滚动条"
（类似微信聊天窗口的条）：

| 输入 | 行为 |
|---|---|
| 鼠标悬停在某块上 | 选中它（高亮竖线），滚轮即可上下滚 |
| **`↑`/`↓`** | 在三个子框之间移动**小光标**（TIME 没展开会先展开它） |
| **`+`/`-`** | 滚动当前选中的那个框（每按一次约 44px） |
| 鼠标移出 TIME | 取消选中，回到默认视图 |

选中 **课表** 时会**按天铺开一整天的课**（`10-15 · 今天` 这样的小标题）。
日期字串直接用内核给的 `date`，**不自己算星期几**（项目铁律）。

实现要点：悬停用**事件委托**绑在 `#time-cards` 容器上 —— 三个框每次 `renderTime()` 都会重建，
绑在框本身上会随重建失效（这类"局部重渲染"最常见的坑）。
子框之间的切换有**过渡动画**（`transition: max-height / flex-grow / border-color`）。
★ **高度必须用显式数值上限来过渡**（用户 2026-10-15 报的闪烁根因）：`flex-basis: auto`
意味着"基准高度 = 内容高度"，聚焦那块**动画还没开始就已经是满高**（12 节课的内容高度），
看起来就是"从最顶端直接渲染"、其余两块被瞬间挤扁 ⇒ 闪烁。现在收起态给数值上限
（next 152 / due 268 / alert 84），聚焦时放大到 2000 ⇒ 生长是**从当前高度延伸出去**的。
`max-height: none` 不参与过渡，所以任何一处都不能用 `none`。

★ 另外两条防空转 / 防跳顶的处理：
- **内容没变就不碰 DOM**（↑/↓ 会重画三块，其中两块内容其实没变）
- **换 `innerHTML` 要保住 `scrollTop`** —— 否则一按方向键内容就跳回顶端
- `scrollbar-gutter: stable`：滚动条出现/消失不再推动布局（那也是一次闪烁）

## 设置界面（用户 2026-10-15）

时钟右边的**齿轮**打开。参数写进 `localStorage` —— 墙上的 kiosk 会被重启，不存就白调了。

| 参数 | 默认 | 参数 | 默认 |
|---|---|---|---|
| 面板轮换间隔 | 20 秒 | 温度 黄 / 红 | 85 / 95 |
| 课表默认节数 | 2 | CPU 黄 / 红 | 75 / 90 |
| DDL 显示条数 | 5 | RAM 黄 / 红 | 75 / 90 |
| 内网 PING 黄 / 红 | 10 / 50 ms | 公网 PING 黄 / 红 | 100 / 300 ms |

★ 铁律：**所有可调参数都从 `setting("key")` 读，别处不许写死数字** —— 否则设置界面里改了、
某个角落没生效，这种 bug 最难发现。渲染测试有一条断言专门守这条（`阈值全部走 setting()`）。

实现：`activeIndex() = 鼠标悬停 ?? 自动轮转`，轮转用 500ms 轮询 + 时间戳判断（这样"暂停/重置"
只是不去更新时间戳，不需要管理定时器）。悬停/移走独立成 `setHover()` / `clearHover()`，
测试可以直接调（DOM 事件在测试替身里没有）。

> **底部是"预留条"**（用户 2026-10-14）：原来那条页脚（`数据源… OL n/4 · 刷新于…`）已删，
> 换成 `<div id="dock">` —— **空占位、固定 64px**，将来做**对话框与交互区**。
> 要点是"留一条空的"，**不是把这块高度让给面板**（否则以后往里放东西布局会跳）。
> 现在只有一圈很淡的虚线标出位置，做交互时去掉即可。
> 删原页脚时**同时删掉了写 `#updated` 的脚本** —— 元素没了还去写 `textContent` 会直接抛错。

## 布局（用户 2026-10-13 定的方向）

三栏，从左到右：

1. **`DATACENTER`**（373px）：四台机器的 CPU / TEMP / RAM / THREADS
2. **`NETWORK`**（373px）：上半内网（逐机 UP/DOWN/PING），下半外网（MAIN WLAN + WAN 通断）
3. **`TIME`**（占满剩余宽度）：接入**时间管理 Agent** —— NEXT / DUE / ALERT

第三栏特意给足宽度：课程名和作业名是长中文（"示例课程G"），
窄栏会折行折得很难看。它的数据源是只读桥 [../time-panel/](../time-panel/)（:8091）。

## 状态语义（用户 2026-10-13/14 定的，别改错）

| 新鲜度 | 竖线 | 状态字 | 数据区 |
|---|---|---|---|
| < 10 秒 | 绿 | `OL` | 正常显示 |
| ≥ 10 秒 | 黄 | `LOST · N 秒前` | 仍显示（还没到关机） |
| ≥ 15 秒 | **灰** | `OFFLINE · N 分钟前` | **只写 `OFFLINE`**，冻结值全部盖掉 |

> 阈值取 10/15 秒，是因为**采集间隔就是 5 秒**：阈值压在采样周期上会在每次采样到达前
> 闪一下黄（用户 2026-10-14 观察到的"刷新率对不上"）。10/15 = 连丢 2/3 个采样。

红色（`bad`）只表示"这台有问题"（温度 >95、速率 0、PING 不通），**不表示"这台不在了"** ——
灰和红语义不同，不能混。从未上报过的机器（如关机的 WORKSTATION）显示 `未上报` + 占位行。

## SERVICE 面板 · OCGO 余额（2026-10-15）

第一个子块 = **OpenCode 余额**。数据不由本壳直接取（凭据在 Windows 上），而是：

```
apiusage panel（Windows）→ CENTRAL/scripts/qyn-opencode-post.py（每 60 秒）
   → POST 状态墙 /api/telemetry，node = svc-opencode → 本壳从 SSE 流里读 sample.frame
```

契约在 `OPENCODEGO/apiusage/docs/INTERFACE.md`（对方维护）—— 业务规则**全部由对方算好**，
本壳**只渲染**：等级直接用 `level`，阈值不硬编码，`usable_percent: null` 显示"无数据"而不是 0%。

### ⚠️ 一处**有意偏离契约**：进度条的填充方向

契约写的是"算进度条用 `usable_percent`"（即条 = **剩余**）。但实测读起来会反：
条填 77% 会被读成"已用 77%" ✗。用户 2026-10-15 选定 **填满 = 用光**，所以：

* 条宽 = `100 - usable_percent`（**已用**占比）—— 唯一不直接用契约字段的地方
* 数字那格明写 **`剩77%`**、右侧 `剩 $9.28` ⇒ 两种读法都不会误读
* 颜色仍严格取自契约的 `level`（**不复算等级**）

⇒ 以后看到这里"跟契约不一致"，那是**故意的**，别当 bug 改回去。

## 灯（lamp）系统 —— 飞机驾驶舱逻辑（用户 2026-10-18 定）

> 用户原话："你可以简单记一下我们的设计逻辑：**飞机驾驶舱**。如果所有系统工作正常
> 完全不需要注意，那么**一眼看过去应该是除了绿色之外没有颜色**。"
> "**离线的系统就不亮灯，代表没电**"；"需要注意但不紧急 = 黄"；"影响生活 / 系统无法运行 = 红，立刻处理"。

### 四条语义（全墙只有这四态）

| 状态 | 灯 | 含义 |
|---|---|---|
| `ok` | **绿** | 一切正常，不需要注意 |
| `warn` | **黄** | 需要注意，但不紧急 |
| `bad` | **红** | 影响生活 / 让系统无法运行 ⇒ 立刻处理 |
| `off` / `none` | **不亮** | 没数据 / 离线 = **没电**，**不是告警** |

⇒ 全部正常时，屏幕上**只剩绿色**——这是判断"要不要看它"的唯一信号。

### 一处映射，所有模块共用

```css
.ok { --lamp: var(--ok); }      .warn { --lamp: var(--warn); }
.bad { --lamp: var(--bad); }    .none { --lamp: var(--lamp-off); }
.off { --lamp: var(--lamp-dark); }
.card, .netcard, .tcard { border-left: 5px solid var(--lamp, var(--faint)); }
```
**新增模块不许再写颜色** ✗ —— 只要带上 `ok/warn/bad/none/off` 之一，就自动接入。

### 一把登记表，供将来的两盏主灯

```js
lightSet(id, 标签, "ok|warn|bad|off")   // 模块渲染时登记自己
lightSummary()                          // → { worst, masterWarning, masterError, bad[], warn[], off[] }
```
* **主警告（红）** = `lightSummary().masterWarning`；**主错误（黄）** = `.masterError`
* **已上线**（2026-10-18）：右下角空挡两个按钮 `MASTER WARNING` / `MASTER CAUTION`（42px 高、14px 字），
  样式照波音件（**黑底刻字透镜**，点亮时字样发红/琥珀，未点亮时透镜是暗的）
* **按下 = 屏蔽「最近一个」致因**（用户 2026-10-18 定，比真实件的"全复位"更细）：
  * 每次"出问题"都会拿一个**因果号 `since`**；按一下只按掉**最近**那一个同级致因
  * **临时、只隔断这一次因果** —— 那个模块状态一变（新的因果号）就**恢复生效**
  * ⇒ **新亮的警告照样能点亮主灯** ✓；其余致因还在则主灯继续亮 ✓
  * 悬停标题会写"已按掉 N 项 / 最近按掉：谁"，便于事后追溯 ✓
* 汇总时 **`off` 不参与**（没电 ≠ 故障）；超过 `LIGHT_STALE_MS`（10s）没登记的模块按 `off` 算（渲染停了就不该报警）
* **汇总与"当前在看哪一页"无关** ✓（驾驶舱的主灯必须反映**所有**系统）：`render()` 每 1.5s 把
  TIME/AGENT 的子框也刷一遍（`setBox` 有 className/innerHTML 缓存，不重画）。否则隐藏的面板会因
  "10s 没登记"被判成没电 ⇒ 主灯随切屏**忽亮忽暗** ✗（用户 2026-10-18 报过，已修 + 有回归断言）
* `setBox()` 会给 TIME/AGENT 的每个子框自动登记；机器卡/网卡/WAN/SERVICE 各块在各自渲染处登记一行

### 已登记的模块

`dc:<机器>` · `net:<机器>` · `net:wan` · `box:next|due|alert` · `box:aplan|aslots|arules|awarn` · `svc:ocgo` · `svc:egress` · `svc:ds` · `svc:svc-wechat` · `svc:svc-agent`

### 语义细节（2026-10-18 这轮定的）

* **异常**：`high` ⇒ 红；**有任何异常** ⇒ 黄；0 条 ⇒ **绿**（以前"没问题"写成 `none`＝不亮 ✗）
* **规划依据**：加载到规则 ⇒ **绿**（以前硬编码 `none` ✗）
* **软偏好**：碰了 ⇒ 黄；**排不上（有 DDL 却没位置）⇒ 红**；都没有 ⇒ **绿**
* **OCGO 例外**：用量高**不动**状态条（进度条仍按 80% 标黄），只有额度耗尽 / 出口不通才红
* **状态词统一 `OL` / `OF`**（用户 2026-10-18：「SERVICE 界面的 OL 又变成正常了，改回去」）：
  `SVC_LABEL`（余额卡）与 `SVC_NODE_LABEL`（AGENT / EGRESS / WECHAT 拆块）的 ok 都写 **`OL`**，
  critical 写 **`OF`**；余额偏低仍写「偏低」，warn 的节点卡写 `LOW`
* **"正在跑的一轮" = 正常**（用户 2026-10-18：「接收信息时不该报黄」）：
  `agent-probe.py` 里"有开始没结束"原来直接给 `warn` ✗ ⇒ 接收/调用 agent 途中整帧变黄 ✗。
  现在：**运行时间 ≤ `STUCK_SECS`(1200s) ⇒ ok**，值写「运行中 Ns」；超过才算可能卡住 ⇒ warn
